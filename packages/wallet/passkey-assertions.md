# Passkey assertions

`verifyPinnedAssertion(ceremony, relyingParty, credential, intent)` is the device-side verification ceremony for a `PinnedCredential` (credential ID, SPKI public key and `ES256` or `RS256`). It issues a fresh random challenge, asks the ceremony (`browserAssertions`, with `browserRelyingParty()`) for a `get` pinned to that credential with user verification required, and verifies the signature, `webauthn.get` type, challenge, origin, RP ID hash, credential ID, UP and UV with `@passwordless-id/webauthn` without a counter check, so synced credentials with zero counters pass. The `Entry` intent sends no PRF extension and returns `EntryVerified`; an `Operation` intent names its `OperationPurpose` and PRF inputs and returns `OperationVerified` with the outputs wrapped in `Redacted`. Outcomes: `PasskeyCancelled`, `PasskeyFailed`, `WrongCredential`, `AssertionRejected` and `PrfOutputMissing`.

## Display lock

`unlock()` reads the stored `PinnedCredential` and verifies a fresh assertion with the `Entry` intent, which sends no PRF input, so it can never open the envelope or authorize a signature; it returns `Unlocked`, or `NoWallet`, `PasskeyCancelled`, `PasskeyFailed`, `WrongCredential`, `AssertionRejected`, `UnsupportedDevice` or `CorruptDeviceWallet`. `makeDisplayLock(now)` holds the tab's display state in memory only and never reads storage: it starts `Locked`, and `unlock(ticket)` applies only to a ticket from `begin()` that no `hide` or `relock` has outdated, so a verification that completes after the page was hidden leaves the display masked. `hide` masks an unlocked display, `show` restores it when less than `resumeWindowMillis` (60 seconds) of wall-clock time has passed and locks it otherwise, and `relock` locks a page restored from the browser cache without a window. Verified `Restored` and `WalletEnrolled` outcomes unlock the display of the tab that ran them. Openings have no assertion path yet, so they unlock nothing.
